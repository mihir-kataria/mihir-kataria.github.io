# Before and after: API documentation

This sample compares one endpoint from AIAG's original internal API notes with my rewrite of the same endpoint. The original notes were written for an earlier version of the system. I rewrote them against the current code, for frontend developers who call the backend.

## Before

The original notes, with their wording unchanged:

> **'/api/similar_questions' Endpoint**
>
> **Method: POST**
>
> This endpoint accepts POST requests containing a JSON payload with the following fields:
>
> - question: The user's question for which similar questions are to be found.
> - history: Conversation history, if any, which helps provide context for generating responses.
> - activeContainer: (Optional) Specifies the active container type. Valid values are 'discussions' or 'asugpt'.
>
> **Response:**
>
> If the request is successful, the endpoint returns a JSON object containing:
>
> - engine_results: Result obtained from the sentence similarity engine.
> - gpt_result: Response generated by the GPT model.
>
> If the activeContainer field is invalid, it returns an error message.

## After

### Ask a question

`POST /api/similar_questions`

Checks that the question is about the course, retrieves the most similar passages from the course's knowledge base, and returns a generated answer with its sources.

**Request body (JSON)**

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `question` | string | Yes | The student's question, in English or Chinese. |
| `history` | array of objects | Yes | Earlier exchanges in this chat, oldest first. Each object has a `Question` string and an `Answer` string. Send `[]` for a new chat. |
| `language` | string | Yes | `en` for English or `zh` for Chinese. |
| `class` | string | No | The course to search, when the user didn't open AIAG from a Canvas course. |
| `activeContainer` | string | Yes | Set to `asugpt`. |

**Response (status `200`)**

| Field | Type | Description |
| --- | --- | --- |
| `gpt_result` | string | The answer text. |
| `engine_results` | array | The passages used as sources. Empty when the question is off topic. Absent when no passages matched. |
| `human_required` | boolean | `true` when no passages matched. The chat interface then offers to post the question to the discussion board. |

**Example response**

```json
{
  "gpt_result": "Yes. Any editor works, as long as your services build and run in the required framework.",
  "engine_results": [
    { "message": "Is VS Code OK instead of Visual Studio?", "updated_at": "2024-02-03T18:22:10Z", "replies": [] }
  ],
  "human_required": false
}
```

**Errors**

| Status | Cause | Body |
| --- | --- | --- |
| `400` | `activeContainer` is missing or not a valid value | `{"error": "Invalid activeContainer"}` |
| `500` | A required field is missing | Error page |

## What changed and why

- **Every parameter is listed and checked against the code.** The original missed `language` and `class`, and called `activeContainer` optional even though requests fail without it. A reference page is only useful if it's complete and accurate.
- **All three outcomes are documented.** The original described only success, so a developer couldn't know about off-topic refusals or the `human_required` flag that triggers escalation. Reference docs need to cover every case the caller has to handle.
- **Tables replace prose lists.** A table with name, type, required, and description lets a developer scan for the one value they need. This follows the Google developer documentation style guide for reference pages.
- **Errors have status codes and causes.** "It returns an error message" doesn't tell anyone what to fix. Each error now says when it happens and what the body looks like.
- **The page leads with purpose and uses one term per concept.** The rewrite opens with what the endpoint does. It says "passages" throughout, where the original mixed "similar questions" and "sentence similarity engine". It also drops the original's deployment-specific details, which belong in a deployment guide, not an API reference.
